# 文字轉圖片workflow

用 A1111 把一段文字變成圖片，途中三次停下來讓你確認（LangGraph interrupt，工作流頁面會跳出表單）。

1. **列出底模類型**：讀 A1111 的 checkpoint，依底模分組（Illustrious、Pony、SD 1.5、SDXL、Anima…；
   Civitai Helper 有記錄的用記錄，沒有的看檔名）。
2. **輸入關鍵字與底模**（人）：想畫什麼、用哪種底模，也可以指定 checkpoint。
3. **輸入人物範例關鍵字**（人）：貼一段喜歡的人物 prompt；留空就跳到第 6 步。
4. **分離範例特徵**：把範例拆成人物特徵、衣服服裝、場景（和品質 / 風格標籤）。
5. **調整範例特徵**：依你的關鍵字改寫這三組，沒提到的保留範例的。
6. **統合成底模關鍵字**：組成該底模的寫法（Illustrious 用標籤＋`masterpiece, best quality, amazing quality`、
   Pony 加 `score_9…`、Anima 用句子＋標籤、Flux 用句子…），附 negative prompt 和使用這些關鍵字的理由。
   這一步 LLM 可以自己挑 MCP 工具先查資料（`tools="auto", read_only=True`）：例如找本機有沒有這個角色 / 畫風的
   LoRA（限同一個底模）、它的 trigger words 與範例 prompt，再把 `<lora:檔名:0.8>` 和 trigger words 寫進去；
   只給查資料的工具，不會生圖、換模型或下載。查過哪些工具會顯示在下一步的審核表單。
7. **人工審核關鍵字**（人）：看 prompt 和理由，可以直接改 prompt；不符合就寫意見重來。
8. **生成圖片**：用選好的 checkpoint 在 A1111 生圖（SD 1.5 用 512×768，其他用 app 的生圖設定）。
9. **LLM看圖檢查**：讓模型看圖判斷有沒有畫對（模型要有視覺能力，沒有就略過）；
   連續 2 次不符合就交給人判斷。
10. **人工確認圖片**（人）：符合就完成；不符合就寫意見重來。

第 7、9、10 步「不符合預期」時，帶著意見回到第 4 步重新調整（沒有範例時第 4、5 步會直接略過）。

輸入可以留空；也可以先打一段文字，會當成第 2 步關鍵字的預設值。等你填表時不算在執行時間上限裡，
但頁面要保持開著（關掉或重新整理就會停止這次執行）。從聊天的 `/workflow` 執行時沒辦法填表，請在工作流頁面執行。
